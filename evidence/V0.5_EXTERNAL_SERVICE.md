## Claim
PrivateRisk can execute the canonical fraud-decision flow across a real HTTP service boundary while preserving the authority and privacy split:

`payment event → external signed attestations → browser verification → local PLONK proof → deterministic policy → server hash-chain audit`

## Key-custody boundary

The V0.5 service creates issuer P-256 private keys inside the Node service process. The browser/API payload receives signed attestations and public JWKs only. The CI self-test asserts that registry responses do not expose a `privateKey` property.

This proves a **service boundary**, not production key custody. Production issuers still require HSM/KMS or equivalent controlled custody, rotation, revocation and service authentication.

## Audit integrity

The server audit store is append-only for the process lifetime. Each entry includes:

- sequence index,
- previous hash,
- idempotency key,
- receive timestamp,
- decision record,
- SHA-256 hash over the canonical entry core.

The self-test mutates an existing audit record after creation and confirms `verifyAuditChain()` detects the corruption.

This is tamper-evident pilot evidence, not a substitute for a durable production database/event store.

## Truth boundary

V0.5 is a **service-boundary prototype**. It does not claim bank-production readiness, durable cross-restart storage, production Kafka connectivity, HSM/KMS custody, mTLS/workload identity, HA/SLOs, regulatory approval, live fraud-model performance or Midnight Preprod settlement.
