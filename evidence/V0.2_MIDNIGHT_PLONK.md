# PrivateRisk V0.2 — Midnight PLONK Evidence

## Claim

PrivateRisk can prove that a **private synthetic balance of €27,000 satisfies a public €15,000 transfer threshold** without disclosing the raw balance as public contract state.

## Contract

`contracts/midnight/privaterisk.compact`

The Compact circuit receives:

- `requestId` — public/disclosed policy context
- `transferAmount` — public/disclosed threshold
- `privateBalance()` — private witness

The circuit asserts `privateBalance >= transferAmount`, records the request id to prevent replay, and increments an on-ledger proof counter. The raw balance is never inserted into ledger state.

## Real ZK pipeline evidence

GitHub Actions run: **34906492162**  
Commit: **113bf6a430d01f74f3afdcaeacdb63613d725566**

The workflow:

1. installed Compact toolchain `0.31.1`
2. compiled the contract **without `--skip-zk`**
3. generated ZKIR plus PLONK proving and verifier keys
4. executed the compiled circuit with the private balance witness
5. serialized proof data with `proofDataIntoSerializedPreimage(...)`
6. verified the result using `@midnight-ntwrk/zkir-v2` `check(...)`

Result: **PLONK checker accepted**.

The same run also passed three circuit-semantics tests:

- €27,000 private balance / €15,000 threshold → accepted
- €14,999 private balance / €15,000 threshold → rejected
- reusing a verified request id → rejected

## Truth boundary

This evidence proves the **real Compact → PLONK/ZKIR proof pipeline is valid for the tested inputs**. It does **not** yet claim that the browser demo generates proofs live or that the contract has been deployed to Midnight mainnet/preprod.

The browser demo replays the same verified predicate outcome while keeping the proof-generation boundary explicit. A network deployment / client-side proving adapter is the next integration step.
